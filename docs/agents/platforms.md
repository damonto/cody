# Platforms and persistence

Read this guide for runtime entry points, deployment, SQL/Redis coordination, reporting or usage delivery. Read [Configuration](configuration.md) before changing schema or configuration persistence.

## Runtime boundaries

| Platform   | Entry           | Durable state                | Coordination    | Inbound WebSocket |
| ---------- | --------------- | ---------------------------- | --------------- | ----------------- |
| Cloudflare | `src/worker.ts` | D1 + Durable Objects         | Durable Objects | Yes               |
| Node.js    | `src/server.ts` | SQLite, PostgreSQL or libSQL | Redis           | Yes               |
| Vercel     | `src/vercel.ts` | PostgreSQL or libSQL         | Redis           | No                |

- Keep the shared Hono application in `src/app.ts` runtime-neutral. Keep Cloudflare dependencies in Worker entry/object shells; derive binding types from generated `Env` through `src/platform/bindings.ts` and use narrow dependency types.
- Cloudflare supplies `REQUEST_BODY_LIMIT_BYTES` at both the entry Worker and HTTP executor (16 MiB, leaving memory for decoded text, JSON and adapter copies within the 128 MB isolate limit). Vercel supplies its documented 4,500,000-byte upload ceiling. Inference, management and configured-search readers take the smaller of the runtime ceiling and their operation budget, including after decompression. Node retains a 64 MiB inference budget; reverse proxies, Cloudflare account-plan upload limits and upstream APIs may impose smaller limits. Never raise application buffering budgets to match a host's transport ceiling. Keep shared limits in `src/shared/payload-limits.ts`; builds do not read deployment state.
- Standard direct HTTP and WebSocket transports are injected through `UPSTREAM_HTTP`; do not register a process-global WebSocket connector. Node/Vercel direct HTTP uses `src/platform/standard/http.ts` to remove hop-by-hop headers and, after native fetch decompression, the same stale body metadata as the SOCKS/native decoders. Preserve encoded metadata for bodyless responses and unsupported encodings; do not apply this normalization to Worker fetch. Native HTTP and rejected WebSocket handshakes share `http-response.ts` for streaming decompression and cancellation. Return rejection headers immediately without waiting for the upload producer's asynchronous cancellation, and leave bounded error inspection to the caller; never silently truncate the transport body. Regression coverage: `tests/standard-http.test.mjs`, `tests/standard-websocket.test.mjs` and `tests/standard-server.test.mjs`.
- Standard runtime implementations live in `src/platform/standard/`. Require Redis coordination and SQL durable state; never substitute in-memory production state. libSQL uses native-free `@libsql/client/http`.
- `cached-objects.ts` serves health/quota/rotation, affinity, session-index, proxy and encrypted OAuth reads from Redis. Mutations remain SQL-fenced write-through operations. Mark the cache dirty before SQL commits, publish only while holding the same Redis lease, and advance the SQL fence when recovering a missing/dirty cache. Never replace this with an unfenced cache-aside write or asynchronous SQL persistence. Cache bounded session-index pages rather than loading the whole index.
- Dedicated `affinity/xai-replay:*` objects are disposable encrypted Redis state with native expiry and owner-checked atomic writes. Their one-hour replay lifetime is separate from durable affinity. Usage outboxes remain SQL-only; durable alarm discovery uses SQL and replay alarm discovery uses Redis.
- Standard runtimes share model-result caches through `MODELS_CACHE`; keys preserve config/client/request variation and local copies cannot extend the shared expiry. Validate the shared payload's response format and bounded expiry before serving it; rebuild invalid entries. The bounded account decode cache reuses only identical ciphertext obtained from coordinated storage; it cannot supply credentials during a storage failure. Read-only projections share deeply frozen decoded snapshots without copying model inventories; lifecycle loads retain detached mutable copies.
- OAuth readiness, views, valid credential resolution and fresh non-forced quota reads may bypass the account writer lease using a clean committed Redis revision. Atomically recheck that revision after decoding, then synchronously validate expiry/freshness and project the result without another I/O boundary. Missing, dirty or replaced revisions fall back to the locked lifecycle; Redis faults fail closed. Token refresh, session expiry and due alarms retain their serialized lifecycle, so inventory network calls cannot block otherwise valid snapshot reads.
- Account readiness checks skip synchronous alarm catch-up so routing cannot start background initialization. Scheduled alarm delivery remains enabled; other object operations retain catch-up on access.
- Session affinity uses one stable client/session object with independent model records. Forward binding digests through status and conditional deletion RPCs on both runtimes. The index persists the model alongside the tuple digest; Cloudflare upgrades only the object's local index table, with no business SQL or Durable Object migration-history changes.
- Migration `0017_siwc_host.sql` adds a deployment-local SIWC host identity on D1/PostgreSQL (SQLite/libSQL reuse D1). Apply pending migrations before starting the new runtime. This UUID survives process/Worker restarts and is excluded from instance transfer.
- Preserve atomic migrations, SQL stale-write fencing, encrypted OAuth state and durable usage delivery. Reuse connection pools, bound connection waits, and retain idle cleanup with the platform's `waitUntil`.
- Local administrator mode must bind only to loopback. Keep Node and Vercel authentication checks in the standard runtime; Vercel does not support SQLite or inbound WebSocket.

## Cloudflare HTTP execution

Code: `src/platform/cloudflare/http-dispatch.ts`, `src/platform/cloudflare/http-execution.ts`; tests: `tests/worker/http-execution.test.ts`.

- Registered HTTP inference requests execute in one `HttpExecution` object per request. The entry Worker forwards streams without parsing bodies; authentication, routing, adapters and usage observation run inside the executor. WebSocket upgrades retain their separate path.
- Each executor accepts one request. A failed dispatch cancels that executor without resending inference: the upstream may already have started.
- Client disconnects cancel through a separate RPC, including before upstream headers and during blocked response writes. Complete pending usage-journal writes before cancellation finishes.
- Do not persist request bodies or tokens in the executor's own storage. Preserve the existing account, health and session objects for coordination.

## Builds, deployment and migrations

- `build:cloudflare` builds the console and runs `wrangler deploy --dry-run`; it does not deploy. `build:node` and `build:vercel` bundle code/assets without connecting to SQL. Vercel output lives in `.vercel/output/`.
- `deploy:cloudflare` builds the console and applies pending D1 migrations before deploying. Configure target account KV/D1 bindings in `wrangler.jsonc`. Use Workers Builds Git integration from `main` for automatic deployment; do not add a GitHub Actions deployment workflow unless requested.
- `deploy:node` and `deploy:vercel` build, then run `npm run db:migrate`. `vercel.json` uses `deploy:vercel` as its build command, so migration failure blocks deployment. Never run migrations in Vercel request handling.
- PostgreSQL migration locks and writes share one transaction/connection. D1 uses `migrations/d1/`; SQLite/libSQL reuse those files plus `migrations/sqlite/`; PostgreSQL uses `migrations/postgres/`.
- Preserve all recorded Durable Object migrations and stable object addresses in `wrangler.jsonc`: notably the v7 `ServiceHealth` → `ProviderHealth` rename, v8 proxies, v9 OAuth accounts, v10 HTTP execution and v11 retired publisher deletion. Retaining history does not mean restoring the publisher architecture.
- `CODY_CONFIG_KV` contains public provider metadata only, never authoritative configuration or OAuth state.
- Offline SQL restores/transfers must invalidate the affected Redis cache before traffic resumes; the runtime rebuilds it from fenced SQL on access. Do not restore stale Redis cache snapshots over current SQL. SQL-only replay conversion is retired; replay uses Redis exclusively.

## Usage and reporting

Start with `src/telemetry/`, `src/reporting/`, `src/platform/standard/usage.ts` and `src/maintenance.ts`.

- Meter selection freezes the canonical reporting `model` (for example `gemini-3.8-flash`) before usage delivery. New events persist the exact execution model separately as `upstream_model` in request details; price/context lookup uses it. This additive v2 metadata is optional when reading historical or queued events: preserve absence rather than infer a variant, and validate its type when present. Reports filter and aggregate stored `model` directly, without SQL normalization or configuration-dependent reinterpretation.
- Optional v2 `upstream_observation` stores final request and original upstream response model/reasoning metadata in request JSON. HTTP passthrough observation binds to the exact final `Response`; replacement responses cannot inherit its provenance. HTTP and WebSocket observations share parsing and terminal-event classification. Preserve historical absence; legacy `reported_model` can contain adapter-generated values and is not comparison evidence. Compare the requested model with the returned model's final `/`-separated segment; stored values and tooltips retain the complete returned name. Compare explicitly reported effort/mode/budget fields without conversion; missing or incomparable values remain unknown. Differences never affect costs, outcomes, health or retries. Regression coverage: `tests/upstream-observation.test.mjs`, SQL dialect tests and reporting integration tests.
- `METERED_INFERENCE_PATHS` in `src/gateway/protocol.ts` defines HTTP metering and request-list eligibility; derive both from that list. Meter POST Responses, Messages, Chat Completions and Images generation/edit requests, plus Responses WebSocket turns. Image token counters are subsets of existing totals; request JSON retains their counts and charges. Old v2 events read missing image fields as unknown, without repricing. Reports retain existing aggregate metrics.
- Production consumes v2 usage events only. Preserve durable delivery, retry/outbox behavior and metering identities from compiled price versions.
- OpenAI 30m/12h cache-write counters are additive v2 fields with null defaults for historical events. Migration `0018_cache_write_durations.sql` persists them alongside the original duration counters. Finish triggers add only the new metrics; the provisional-correction trigger subtracts/replaces all metrics together to avoid trigger-order dependencies. Keep hourly and partial-hour query expressions consistent, and preserve unknown counts across retry attempts for all four cache durations.
- HTTP JSON/SSE usage observation and retry inspection have distinct 16 MiB budgets in `src/shared/payload-limits.ts`. Count raw bytes for JSON/retry reads and UTF-8 bytes for assembled SSE data, including newlines joining data fields but excluding field prefixes. Results must not depend on transport chunking; scan each incoming SSE chunk once. Oversized payloads record observation issues without changing forwarded responses; exhausted retry-inspection budgets commit forwarding and prohibit replay. Regression coverage: `tests/response-observer.test.mjs`, `tests/telemetry.test.mjs` and `tests/retry-errors.test.mjs`.
- HTTP SSE metering uses one protocol outcome for EOF, cancellation and read errors. Observe chunks after handing them to the metered body's consumer; this is not an end-to-end client acknowledgement. Preserve explicit failures over later incomplete/success markers and keep observing trailing usage during normal reads. A Chat Completions choice's `finish_reason` is not a whole-stream boundary; require `[DONE]` for success, including at EOF. Do not read ahead in the metered stream: unread or partial terminal events cannot turn a cancellation into success. Release the upstream reader on every exit, including cancellation failures. Regression coverage: `tests/telemetry.test.mjs` and `tests/worker/http-execution.test.ts`.
- `npm run data:transfer` copies business SQL tables and encrypted OAuth accounts into a fresh instance. The operator stops traffic and background work; the prompt confirms this precondition. Do not add runtime admission locks or SQL task tables. Health, cooldowns, proxy state, sessions, WebSocket journals, usage outboxes and queues are outside the transfer scope. Do not drain or settle them during transfer; copy the database as stored.
- Cloudflare database transfers use native Wrangler file operations: `d1 export --remote --output` into temporary SQLite for local reads/verification, and `d1 execute --remote --file --yes` for imports. Export blocks database requests and is allowed only in the confirmed offline transfer window; preflight does not export. Stream generated imports to disk, preserve integer precision, keep migration metadata local, and replace trigger-generated hourly aggregates with the source rollups. Standard databases use bounded bulk reads/inserts with one replay comparison per page, never per-row existence queries.
- Validate snapshot secret, OAuth and price-version references in batches per page, since JSON references have no SQL foreign keys. Check SQLite/D1 foreign keys before activation, keep temporary D1 snapshots read-only, and exclude SQLite's internal statistics from business schema checks. Platform adapters supply the complete inventory result; the shared runner does not call Cloudflare APIs.
- `src/transfer/runner.ts` owns the typed workflow and local journal. Import digests are saved before native D1 writes; retries replace only that task's business tables. Standard batch and OAuth retries compare committed contents. Retired task formats are rejected; start a new task with a fresh target. Persist abort intent before restoring source OAuth alarms, and prohibit abort after target activation.
- OAuth ciphertext and account identities stay unchanged. Include disabled/soft-deleted accounts and historical references. Skip unreferenced remnants whose provider no longer exists, without reading/deleting their objects. The temporary authenticated Wrangler preview provides OAuth RPC and preflight only; it rejects table read/write commands and adds no application route. Pause source OAuth alarms and restore target alarms only after content verification. Preserve all deployed SQL and Durable Object migration history.
- Use Wrangler authentication/config resolution, with optional per-side overrides. Never parse private credential files or print captured CLI errors. Protect temporary SQL/SQLite files in a private directory and clean it on exit. Keep task journals and backups out of Git. No queue access or consumer configuration is required. See [the operator guide](../data-transfer.md).

PGlite test adapters must forward `db.close()` to the underlying instance; `tests/helpers/postgres.mjs` supplies this ownership. Register cleanup before migrations or assertions so each test closes its database, including on failure.

Regression starting points: `tests/standard-*.test.mjs`, `tests/sql-dialects.test.mjs`, `tests/deploy.test.mjs`, `tests/data-transfer*.test.mjs`, `tests/worker/data-transfer.test.ts`, `tests/worker/usage-outbox.test.ts` and the Worker HTTP execution tests.
