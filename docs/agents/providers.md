# Provider adapters and accounts

Read the shared rules and the section for the provider being changed. Entry points are `src/providers/index.ts`, `src/providers/types.ts`, `src/providers/credentials.ts`, `src/providers/oauth/` and each provider's directory. Read [Gateway](gateway.md) when changing selection, retries or transport.

## Shared native account rules

- Native providers are fixed optional singletons, disabled by default. Credentials reference accounts owned by that provider. Store tokens encrypted in per-account objects using `CONFIG_ENCRYPTION_KEY`, never in config snapshots. Standard runtimes persist the equivalent object state in SQL.
- Pending authorization uses `authorization_generation`; active credentials, refreshes and observations use `generation`. Starting, cancelling, expiring or retrying authorization must not invalidate an active token refresh. Completing replacement credentials or disconnecting advances both fences. Preserve account identity and omitted token fields; configuration save/restore must not restore old tokens. OAuth/quota application errors do not change inference failure health.
- When replacement authorization omits a refresh token or returns the active token unchanged, coordinate inheritance with its refresh through the durable commit and use the latest committed token. Antigravity project provisioning must retain the inheritance relationship instead of freezing a borrowed refresh token. An older pending project with ambiguous token provenance requires new authorization while preserving active credentials. A grant with a distinct refresh token and a disconnect still fence older credential operations.
- `oauth/account.ts` owns session coordination, token refresh deduplication, encryption and generation-fenced commits. `oauth/registry.ts` composes provider-owned `account.ts` implementations through `oauth/provider.ts`; each provider owns authorization protocols, identity, initialization, token grants, inventory merging and optional reset/background capabilities. Committed snapshots are deeply read-only and frozen; updates edit detached copies and become visible only after durable commits. Providers retain the operation's original generation even if execution is deferred. `oauth/inventory.ts` coordinates refresh errors and uses the same freshness rule as presentation; `oauth/initialization.ts` completes the shared authorization transition.
- `oauth/state.ts` validates provider-discriminated persisted state on load and before commit, retaining existing field names/defaults. Provider `account-schema.ts` files own identity, credential and specialized quota schemas; persisted state must not depend on presentation schemas. `oauth/schema.ts` composes the existing RPC/view contracts and `oauth/presentation.ts` projects account views. Read-only snapshot access and the account lifecycle share pure provider-owned `account-credential.ts` projections with provider-specific return types, without importing account lifecycle implementations.
- The adapter entry uses one lifecycle: request validation, optional local response, credential resolution/validation, then upstream preparation. Validate OAuth identity with the selected provider's credential schema. Local responses, such as xAI models and count-tokens, bypass credential resolution.
- Provider `response-policy.ts` modules own quota inspection, limit persistence and exhausted responses. Prepared requests expose explicit account-switch actions; the gateway switches only after a successful commit and before output. `responseInspector` selects exactly one preflight phase: transport inspection retains the send timeout; retry inspection shares bounded error parsing and the remaining attempt budget. Account-switch timeout scope is explicit. Claude observations run on the final Messages response, including successful responses; count-tokens stays independent.
- `account_selection: round_robin` defaults to rotating new sessions among the highest-priority available accounts. `session_affinity` fills the first available account in priority/configuration order. An available existing binding stays with its account rather than advancing rotation.
- Allocate round-robin bindings atomically in the session object through shared `rotation:<provider_id>` health objects, using the durable provider ID. Coordination failures fail closed. Preserve account provenance when quota switching is allowed.
- Account switching stays within the selected provider and stops before downstream output. Persist explicit quota limits before switching. Generic 429s use only configured retries.
- Claude/xAI paid fallback evaluates the remaining candidates after excluding accounts whose quota rejection was persisted. Previously exhausted accounts cannot block explicitly enabled extra usage; unknown quota or health-read failures among remaining candidates still prohibit it.
- Keep paid usage opt-in and never change upstream billing settings or spending limits. Tests mock paid entitlements and upstream calls.
- Antigravity/xAI requests enforce the shared 16 MiB native request budget on decoded client bytes before credential resolution and on the serialized translated body before sending. All byte budgets use UTF-8, including cumulative xAI output; do not use JavaScript string length except for ASCII envelopes.
- Native SSE events use the shared 16 MiB event budget and bounded `SseObserver` parsing, independently of network chunk layout. xAI requires a complete event terminator, drains parsed events between bounded decode slices and cancels on failure/early return. Keep cumulative output budgets separate (Antigravity 8 MiB, xAI 32 MiB).
- Claude/xAI account JSON reads and Antigravity replay envelopes retain separate 16 MiB budgets in `src/shared/payload-limits.ts`; Codex/Antigravity account metadata uses 8 MiB. Replay sealing and opening enforce the same envelope limit and scope/account validation. xAI also checks its 8 MiB ciphertext limit on both paths before decryption, within the 12 MiB envelope budget.
- Adapters changing inference bodies provide `inferenceMetadata` from the final translated body. Response converters notify the optional metadata observer from original parsed upstream frames before rewriting or synthesizing fields; never report echoed client parameters as upstream evidence. Reuse parsing without an extra stream consumer. Observer failures must not interrupt conversion. Antigravity reads native `modelVersion`; xAI reads native Responses metadata.

## AI Gateway

Code: `src/providers/ai-gateway.ts`, `src/providers/claude-code.ts`.

- Use `Authorization: Bearer <key>` for every request dialect, stripping the client's credentials including `x-api-key`. Preserve upstream payloads and responses unless a configured route or adapter option requires a change.
- `anthropic_1m_context` merges `context-1m-2025-08-07` into the `anthropic-beta` header for Anthropic inference, preserving existing betas without duplicates. Never rewrite the model: `[1m]` is a client-side convention.
- `emulate_claude_code` is opt-in and applies only to Anthropic `messages`. A passing request has a system array starting with Claude Code's prompt prefix (or attribution immediately followed by the prefix), a JSON-string `metadata.user_id` with non-empty `device_id` and UUID `session_id`, and at least three core tools from `Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`.
- Reshape only what those checks require. Reuse usable client device/session IDs; otherwise derive one synthetic conversation from the client API key. Declare missing core tools as stubs and set `tool_choice: none` when no tools were offered. Forward requests already passing the checks byte for byte; drop digest headers only on body change. OpenAI, catalog, count-tokens and WebSocket are untouched.

## Antigravity

Code: `src/providers/antigravity/`.

- Use the built-in public desktop OAuth registration from CLIProxyAPI and official adapter endpoints. No custom base URL, client-registration settings or provider-specific Worker Secrets.
- OAuth completes after token and identity validation. Project setup runs independently in the encrypted account object. Query `loadCodeAssist`, then poll `onboardUser` with a 30-second request timeout until done. Retry unfinished operations and transient transport/HTTP failures using persisted alarms with 5–30 second backoff and a ten-minute deadline. Completed onboarding without a project ID and explicit operation errors stop automatic retries, including over HTTP 200. Keep tokens and the last upstream outcome on failure; manual initialization retries restart project lookup and tier selection. Only a real project ID makes a new account ready; reauthorization preserves the previous working credentials until setup succeeds.
- Selection uses the minimal `readiness` RPC before model cooldowns, skipping accounts still initializing. This check never catches up account alarms on Node/Vercel. Read failures fail closed; initialization never changes inference health.
- `initialization.ts` owns project polling and bounded retry rules; the account object owns encrypted state and fenced commits. Only classified upstream failures change project retry state. Storage failures propagate to the alarm runtime, and background operations use the committed proxy binding when the account is configured.
- Worker OAuth tests wait for the expected session/project state while driving scheduled alarms. An automatic alarm may already be running when `runDurableObjectAlarm` returns, so fixed trigger counts do not establish completion. Drive multi-poll scenarios one committed step at a time instead of fitting the entire sequence into one `waitFor` timeout. Fixtures testing pending setup must keep `onboardUser` unfinished until explicitly released. Wait for the current step to commit before eviction or replacing mocks, and for the error state before testing manual recovery.
- When no project was assigned, honor the selected tier's `userDefinedCloudaicompanionProject` requirement and explicit `ineligibleTiers` before onboarding. Age/account verification takes priority over the project prerequisite. Parse Google RPC `ErrorInfo` on HTTP failures and completed operation errors as well. Retain actionable verification messages and validated Google HTTPS links in encrypted account state for the authenticated console; never log challenge URLs. Stop automatic retries until the user completes verification and retries. Never substitute a shared project ID. A real assigned project remains usable regardless of an unrelated tier's eligibility or the tier flag.
- `Credits.credit_amount` is an implicit-presence proto3 int64 in the official Antigravity 2.19.1 protocol. An omitted/null amount in a credit entry means zero; a missing credit inventory is not a known zero balance. Preserve integer strings without precision loss. Credits are informational; never enable credit spending.
- Normalize tier eligibility fields and RPC metadata separately. Prefer Google's specific verification action (`ErrorInfo`, then `Help`) before a generic age-verification page. Merge repeated requirements without losing distinct instructions or help links; quota/subscription partial failures must retain both errors and the last successful data. Console verification actions must not hide a simultaneous refresh error.
- Follow CLIProxyAPI request conventions: native header whitelist, Messages-only conditional interleaved-thinking hint for Claude thinking models, and removal of Claude Code billing attribution. Keep the old identity prompt disabled.
- Agent requests omit recognized optional Responses/Messages web-search tool declarations, including nested declarations, while retaining function/custom tools. Reject forced native search and required selections with no available tools. Apply `allowed_tools` to active declarations without losing mappings for historical calls. Completed Responses `web_search_call` records are omitted as server execution metadata; preserve the surrounding assistant content and signed parts. Native search envelopes and grounding conversion are not implemented or advertised; the global `supports_web_search` flag controls the separate `alpha/search` endpoint.
- Optional `sensitive_words` masks system text only. Never mutate conversation/tool history or native signatures. Signed history may move among configured accounts only after verifying client, provider, model and original content; retain source-account provenance.
- Preserve available bindings across credential-priority recovery. `QUOTA_EXHAUSTED` and timed `RATE_LIMIT_EXCEEDED` cool the physical account and real upstream model, then permit an account switch before output. Inspect the first SSE event before committing the stream; later limits cool without replay. Unknown/capacity 429s only use configured retries.
- Persist quota cooldowns at `quota:antigravity:<account_ref>:<encoded model>`; lookup/write failures fail closed.
- Gemini `-low`, `-medium` and `-high` variants form a derived client-facing family when no real bare model is configured. Keep physical IDs in provider configuration and account discovery; catalogs, model selectors and the metered reporting model expose the family. `-tiered` and other suffixes stay independent. Explicit physical targets remain fixed.
- Resolve families before account selection and quota checks. Responses `reasoning.effort` and Messages `output_config.effort` select the variant; explicit thinking budgets take precedence (0–1024 low, 1025–8192 medium, larger high), and disabled/none selects low with disabled thinking parameters. Minimal maps to low; xhigh/max to high. Absent/auto/adaptive effort defaults to high. Missing configured levels are errors, never implicit fallback or configuration changes.
- Normalize reasoning into a typed mode before routing or native translation; reject malformed reasoning objects, unknown modes and empty efforts. Keep budget tables and native constraints inside `reasoning.ts`. Retries and quota account switches retain the resolved physical model, as do price lookup and replay signature scopes. Usage stores the canonical family in `model` and the execution variant in `upstream_model`. Responses retain the requested client model name. Signed history cannot cross physical variants; never strip or relax signatures to support an effort change.
- Cache public Hub version metadata separately from config/OAuth state and refresh through shared maintenance, never on the inference critical path.
- Node/Vercel direct transport uses pooled HTTP/1.1 without ALPN. SOCKS5 also omits ALPN; Worker direct `fetch` keeps the platform TLS implementation.

Tests: `tests/antigravity*.test.mjs` (including family routing/catalog coverage in `tests/antigravity-models.test.mjs`), `tests/worker/provider-oauth.test.ts`.

## Codex

Code: `src/providers/codex/`, `src/gateway/websocket/`.

- This provider balances the operator's own ChatGPT accounts; it is not a resale interface. Native accounts use Codex CLI public OAuth registration for device-code and pasted `http://localhost:1455/auth/callback` PKCE flows. SIWC is a separate account mode; reauthorization cannot change a registered account’s mode. Validate mode in the fenced authorization-start transaction, including when another authorization commits while start is preparing PKCE.
- Before HTTP, catalog and WebSocket account selection, check the minimal OAuth readiness RPC. Disconnected, authorizing-without-credentials and reauthorization-required accounts are unavailable even when health is green. Read failures fail closed; preserve an available session binding.
- A native HTTP 401 (including a WebSocket handshake) permits one authentication recovery on the same account before output. Fence the RPC by account generation and rejected access token; reuse a token already refreshed by another request, share in-flight refreshes and persist rotated tokens before returning them. Permanent refresh failures require reauthorization; transient failures preserve readiness. Never switch accounts for authentication failure or replay an established WebSocket frame. Read-only account inventory queries use the same recovery; reset consumption does not gain a retry.
- Authentication recovery is separate from configured retries: the retry executor owns the one-recovery limit, records both upstream attempts, keeps the original attempt deadline and remaining configured retry allowance, and stops on cancellation. Providers return explicit replacement headers without mutating the prepared request; later retries retain those headers. A failed recovery or a second 401 returns the actual upstream rejection. Inventory reads return the updated credential explicitly for subsequent metadata queries.
- Observe bounded HTTP rate-limit headers and WebSocket `codex.rate_limits` frames without changing response bytes or awaiting observation storage. Bind observations to the actual connection's account generation. Compare timestamps separately for each window, plan and balance; merge partial windows and preserve unrelated groups/reset credits. These observations update account display only; they do not set routing cooldowns or authorize reset spending.
- `codex/quota.ts` owns pure quota normalization and merging; account objects own generation fences and persistence. A full read merges untouched windows, groups and exhaustion state while preserving newer passive fields. Only full reads advance quota freshness or clear full-read errors; partial observations cannot suppress ordinary refreshes. Persist bounded observation clocks with the encrypted account, prune clocks superseded by full reads and reset them on completed reauthorization.
- Read `chatgpt_account_id` from the ID token; email is optional. Carry the FedRAMP claim into `X-OpenAI-Fedramp`. Partial refreshes preserve omitted/null token fields and reject workspace changes.
- Native accounts forward HTTP/WebSocket to `https://chatgpt.com/backend-api/codex`, replacing account authorization and `ChatGPT-Account-ID`. Preserve client payloads; no instruction injection, client impersonation, forced streaming or unrelated field rewriting.
- For HTTP `responses` with an absent or unrecognized response media type, detect JSON/SSE from a bounded prefix during existing reads. Metering, quota inspection and discarded-attempt usage share this parser. Preserve original headers/bytes and preflight budgets; failed detection records an observation issue, and output or budget boundaries still prohibit replay.
- Implemented endpoints are `responses`, `responses/compact`, `images/generations`, `images/edits`, `models`, `memories/trace_summarize`, plus `alpha/search` when its capability flag allows it. Native history/notes are unsupported. `memories/trace_summarize` is OpenAI-dialect inference served only by Codex.

### Sign in with ChatGPT (SIWC)

Code: `codex/account.ts` composes `native-account.ts` and `siwc-account.ts`; `siwc.ts` owns OAuth transport, and `siwc-policy.ts`/`availability.ts` own request eligibility.

- `flow: siwc` is Codex-only. Start dynamic registration with `dynamic_agent_client`, `agent_name_hint=Cody`, a stable deployment host ID, fresh nonce/state and S256 PKCE. Use the complete official identity/direct-inference scopes and `resource=https://api.openai.com/v1`. Persist the callback’s issued client ID with the verified issuer/subject, and reuse it for reauthorization and refresh. Only an explicit enable-plan action requests `prompt=consent`.
- SIWC uses the exact `http://127.0.0.1:1455/auth/callback` URI. The console deliberately accepts a manually pasted callback, as the existing browser flow does; this differs from the official recommendation to start a local listener first. Never substitute `localhost`. Validate one state/code/client ID, reject replacement client IDs, and consume callbacks once.
- Fetch trusted OpenAI discovery and JWKS through the selected account transport with bounded bodies/timeouts; prevent discovery from redirecting credentials to another origin. Verify RS256 signatures, issuer, issued-client audience, expiration, subject and the attempt nonce. Treat access-token authentication metadata as opaque. Missing direct permission retains the verified sign-in but excludes inference readiness.
- Persist tokens encrypted in the existing account object; retain the issued registration after disconnect or terminal refresh errors. Rotate access/refresh tokens atomically through shared refresh coordination and generation fences. Disconnect blocks new requests before attempting revocation of the latest refresh token; clear local tokens even on remote failure and report unconfirmed revocation.
- `0017_siwc_host.sql` adds deployment-local `oauth_host_identity`. Generate its UUID server-side on first use with an atomic insert; all runtime instances share it. Data transfer recognizes but never copies this table, so the target keeps its own identity.
- SIWC serves public `/v1/models`, HTTP/SSE `/v1/responses` and Responses WebSocket. Filter model discovery by `visibility: list`. Check account mode and request compatibility before selection, then validate again in the adapter. HTTP requires explicit `store:false`, `stream:true`, full array input and no `previous_response_id`; WebSocket requires `store:false`, omits `stream`, and validates every `response.create`. Reject documented unsupported parameters/tools with their parameter paths; preserve supported bodies and unknown fields without rewriting.
- SIWC does not use native workspace/FedRAMP authentication, private quota/credit APIs, reset consumption or other Codex backend endpoints. Quotas remain unknown unless actually observed; an explicit Refresh discovers models and renews tokens as needed.
- Only `subscription_sharing_usage_limit_exceeded` authorizes SIWC quota switching, before output and after successful cooldown persistence. Once a logical request starts upstream, switches retain its sign-in mode. Honor explicit reset times or `Retry-After`; absent both, use a 60-second internal retry hold and never expose it as the subscription reset. Preserve upstream error bodies and synthesize a SIWC-specific 429 without a reset time when all matching accounts are cooling.

### Quota switching

- A 429 or Responses stream failure with `usage_limit_reached`, `usage_not_included` or `insufficient_quota` terminates configured retries. Share bounded preflight with error-code retries through the retry executor's response inspection result; output-bearing events and size/time boundaries prohibit replay. Await a successful credential quota cooldown before resending on another account of the same provider. Quota read/write failures fail closed; late stream failures cool without replay. Late HTTP cooldown writes use the shared health scheduler so slow storage does not block forwarding.
- Resolve cooldown end from body `resets_at`, then the active limit's `x-codex-*-reset-at` headers, then a 15-minute fallback.
- WebSocket switching covers handshake 429 or a first-frame `error`/`response.failed` before any other upstream event. Wrap HTTP handshake rejections in an error event with `type`, `status`, upstream error details and headers; bound error-body reads by both size and time. Once output starts or client frames overlap, forward the error, cool the account and close; do not replay. Overlapping turns disable recovery for the remaining connection because completion of one response does not establish that all turns have finished. A later non-overlapping turn rejected before its first upstream event may request full replay after the quota write succeeds: verify the client-message sequence is unchanged, send `previous_response_not_found` and close with 1012, letting Codex reconnect and select another account. Fresh Codex sockets reject `previous_response_id` before sending upstream and discard incoming `x-codex-turn-state` hints; the client must supply full current input.
- When no account remains, return the last upstream quota response unchanged. If all were already cooling, synthesize `usage_limit_reached` with the earliest `resets_at`. Ordinary sessions retain an available account across higher-priority account recovery.

### Reset credits

- Reset credits apply only to native Codex accounts. `auto_consume_resets` defaults false. When enabled and all accounts are exhausted, one lease-serialized request may spend the earliest-expiring credit.
- Persist the selected credit and redeem request ID before consuming. Lease takeover replays the same operation, fences late owners and clears only the original quota cooldown. Manual retries retain both IDs.
- Manual consumption always requires confirmation. Credits are paid entitlements: mock them in tests.

## Claude

Code: `src/providers/claude/`.

- Use public Claude Code PKCE registration with pasted `code#state` or the official callback URL. This provider serves the operator's own subscriptions. Partial refresh grants preserve omitted/null/empty refresh tokens and absent identity fields; explicit account or organization changes still fail.
- Serve Messages HTTP/SSE, count-tokens and models only. Preserve native bodies and application headers; never inject prompts, tools, beta headers or client fingerprints. Resets, remote sessions, files and WebSocket are unsupported.
- Model discovery accepts nullable token limits and pagination cursors and retains explicit `thinking`/`image_input` capabilities; missing capabilities remain unknown.
- Filter fresh subscription quota before Messages account selection. Keep five-hour, global weekly and model-specific weekly windows separate; persist model-scoped observations. Missing/stale quota fails closed. Count-tokens has independent rate limits: do not gate it on Messages quota, record its headers as subscription limits or switch accounts on those headers.
- Full quota reads advance freshness even when passive observations arrive concurrently. Track observation revisions per window and Extra Usage restriction, including repeated identical values. Merge observations made during the read without rewinding reset/utilization or losing persisted model limits; take untouched fields from the full read.
- Explicit HTTP 429 subscription rejection may switch within Claude before output, never after SSE starts. Persist subscription rejection headers on HTTP 200 too (upstream overage may be allowed), without replaying the response. `overage`/`seven_day_overage_included` and `7d_oi` alone do not prove subscription exhaustion; independent explicit subscription-window rejections still apply. Unrecognized claims stay scoped to the exact upstream model, never the whole family.
- `allow_extra_usage` defaults false and permits existing paid usage only after subscription candidates are exhausted. Never enable billing or change spending limits; concurrent requests may still cross the upstream billing boundary.

Tests: `tests/claude-provider.test.mjs`, `tests/claude-quota.test.mjs`, `tests/subscription-routing.test.mjs`, `tests/worker/claude-provider.test.ts`.

## xAI

Code: `src/providers/xai/`.

- Use Grok CLI public device authorization; restrict discovery to HTTPS x.ai endpoints. Preserve encrypted storage, generation fencing and account identity through refreshes. Token expiry prefers the new grant's `expires_in`, then the new access token's JWT `exp`, then the previous expiry only if both are absent; zero expiry is explicit.
- OAuth inference uses `https://cli-chat-proxy.grok.com/v1/responses` with native CLI headers. Align Responses/Messages behavior with CLIProxyAPI, including an empty `instructions` default and native search tools. Preserve caller instructions rather than inventing an identity prompt.
- `inject_x_search` defaults false; when enabled, add `x_search` and filter internal search calls from client tool events. API keys, custom base URLs, WebSocket, compact and media generation are unsupported.
- Reasoning envelopes bind client ID, provider, account provenance, model and visible text. Preserve native encrypted content and tool IDs across validated pool switches.
- For recognized sessions, fill omitted reasoning and matching tool calls from the latest completed turn. Store replay state encrypted at dedicated `xai-replay:*` session-object addresses, with sliding one-hour TTL, bounded chunks and fenced writes. Standard runtimes use disposable Redis replay storage; durable account and affinity records retain SQL recovery. Account generation changes invalidate cached provenance; no process-local replay cache.
- Prefer fresh subscription quota. When fresh credits billing reports a zero on-demand cap and no prepaid balance, an unreported percentage may be checked through the actual inference request; this rule is independent of plan names. Otherwise unknown quota fails closed. Respect `allow_access: false`, authentication failures and persisted limits. `allow_extra_usage` defaults false; paid candidates require opt-in after subscription candidates are exhausted. Persist explicit limits before switching; generic 429s only use configured retries. JSON and SSE quota failures share the replay-safety guard: output-bearing failures may update limits but cannot switch accounts or replay.
- Read `/settings` for subscription tier and access; fall back to the current access token's numeric `tier` claim, where explicit `0` means Free. Never infer Free from missing billing fields. Fetch credits and monthly billing independently; preserve partial data and per-source errors. Protobuf Cent `{}` is zero, while missing percentages stay unknown, never zero or derived from monthly spending. Keep subscription resets separate from billing rollovers and never merge amounts with conflicting billing-period ends. Retain the previous snapshot when neither billing data nor a plan is available.
- Approximate count-tokens uses server-only `o200k_base`, makes no upstream call and records no billable inference.

Tests: `tests/xai*.test.mjs`, `tests/worker/xai-provider.test.ts`.
